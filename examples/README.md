# Worked examples

Ten examples include researched inputs and script-generated artifacts. Reports show each
ticker, name, role and brief business reason; full reasoning, evidence and measurement
diagnostics remain in JSON. All project documentation is in English; generated reports
also retain the market-language companion where applicable.

HTML files are complete, dark, responsive reports. GitHub displays their source, so download
and open them in a browser. The Preview column shows actual HTML screenshots: click a
thumbnail for the complete long image, or choose Local image for a market-language capture.
These are dated, static previews, not interactive reports or refreshed research. Research notes
stay collapsed in captures. Open the full image at its original size to scroll through all rows;
download the HTML for selectable text, expandable notes and working artifact links.

Members are grouped by theme. `reason_summary` comes from the business description;
full reasons, admission evidence, market-cap sources and per-ticker measurement diagnostics
remain in JSON, linked at the top of each report. Summaries describe the business directly.
English display text is authored in `report_translations.en` and rendered by the CLI.
Important validation warnings and partial-delivery gaps remain visible; hiding diagnostics
never changes qualification.

Medium directories contain `build-spec.json`, `snapshot.json` and `output/`; all four US
depths share the US Medium snapshot. Max retains all 370 Heavy entities and adds 111 Beta
(30%). Standard artifacts are HTML, Markdown, TXT, authoritative JSON and validation JSON,
selected and rendered by scripts rather than hand-written watchlists.
[build-summary.json](build-summary.json) records counts, qualification and hashes;
[input-provenance.json](input-provenance.json) records sources and summary transformations.
Screenshots live in separate `preview/` directories, so rebuilding artifacts does not delete them.
Refresh them whenever the corresponding HTML changes.

```bash
python examples/build_examples.py

# Public CLI builds write to a new, empty directory.
python scripts/universe.py build \
  --spec examples/us-heavy/build-spec.json \
  --snapshot examples/us-medium/snapshot.json --output temp/example-us-heavy

python scripts/universe.py build \
  --spec examples/us-max/build-spec.json \
  --snapshot examples/us-medium/snapshot.json \
  --seed temp/example-us-heavy/us-heavy-2026-10-08.json --output temp/example-us-max
```

The generator validates every example before replacing artifacts. CLI builds also save
continuation records; see [standard outputs](../references/output-artifacts.md).
Rebuilding uses saved facts and does not refresh them online.

## Refresh image previews

Screenshot generation is an optional documentation task, separate from the dependency-free
Python runtime. It uses Node.js, Playwright and an installed Google Chrome browser:

```bash
npm install --prefix temp/preview-tools playwright
NODE_PATH="$PWD/temp/preview-tools/node_modules" node examples/render_previews.cjs
```

The script captures all 14 HTML reports at 880 px width, saves a top-of-page preview and a
full-page JPEG for each, and refreshes the root README's US Medium desktop/mobile images.
It checks rendered row counts against authoritative JSON and checks desktop horizontal overflow.
Its capture receipt is saved to `temp/report-previews/capture-receipt.json`.
No HTML content, membership or research input is changed.

HK/UK correct inactive codes and supplier business-data mismatches; see
[HK review](hk-medium/research-review.json) and [UK review](uk-medium/research-review.json).
JP/KR preserve original prices, dates, measurement populations and hashes; see
[JP review](jp-medium/research-review.json) and [KR review](kr-medium/research-review.json).
HK ranks liquidity across 123 HKD histories; UK uses 128 collected histories, normalizing
GBp/GBX turnover to GBP. Investment fund SMT belongs to the measurement population only,
not the watchlist. Theme factors use leave-one-out baskets of the same economic duty;
fewer than three histories do not establish a measured theme regression, and a broad-market
index is not substituted.

The CN snapshot retains 457 reviewed Heavy candidates, insufficient for a qualified Max;
US retains all 667 candidates. HK/UK/JP/KR Medium cover principal business representatives
within a declared scope; they provide no Beta bench and do not claim every leader was reviewed.
Unknown supplier financial periods remain unknown; losses and missing cash-flow fields are
recorded per ticker. Raw prices and network receipts are not distributed. Measurement
populations and hashes are not rewritten to match the example subset.
Qualification means evidence contracts, coverage and capacity checks passed; it does not
independently prove leadership judgements, market-wide optimality or TradingView UI import.
See the [complete online validation record](../docs/validation/codex-online-2026-10-08.md).
