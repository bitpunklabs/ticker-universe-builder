# 0.11.0 — Reviewed Global Core

Date: 2026-10-18. Global Core is a researched, strictly smaller subset of a qualified Global
composition. It is not another native-market depth, a capitalization screen or a renamed export.

## Review 1: preserve the denominator

Inherit every market, theme, child duty, minimum, required/excluded ticker and ETF gate from
the independently pinned parent contract. Review every parent ticker exactly once. A reduction
cannot erase an operating theme or country merely because its remaining instrument is small.
Keep original native source-theme IDs; explicitly record slices represented through another
retained Global source instead of silently deleting their lineage.

## Review 2: choose representatives by business function

Start with theme relevance, leadership and continuing quality; market cap, profits and familiar
names alone are insufficient. An advertising-channel franchise cannot replace a content/platform
duty solely because it produces more cash. Concentrated franchises normally favor leaders;
dispersed businesses favor a credible basket plus essential differentiated leaders. Investigate
1–3 leaders per child function, allowing explained composite exceptions rather than imposing a
quota. A good ETF is not removed just to reach a headline count.

Retain/omit decisions carry dated evidence. Every omission names retained instruments that
preserve its declared duties. An omission is a Core-priority judgement, not an assertion that
the company or fund fails full-universe admission. ETF exposure requires actual holdings review,
not a fund label or an assumption that a broad index covers every child business.

## Review 3: portable proof and delivery

`compose-global-core` takes a qualified parent JSON, its independent contract, and a separate
review contract pinning both file hashes. Revalidate the complete parent before deriving anything.
Use original source rows and selection assertions without role promotion, ticker substitution or
new measurements. Inherit the parent's as-of date; a subset build does not refresh its evidence.

The portable Core bundle contains byte-preserved parent JSON, all three parent TXT views, parent
contract and native source copies. Independent validation recomputes the parent and Core from
the external expected review, detects changed parents/decisions/coverage/sources/exports, and
checks strict subset membership. New directories publish atomically only after all gates pass.

Main `global-core-DATE.txt` is ticker-only. Two grouped views retain exactly the same tickers.
Reports disclose the reduction, coverage, evidence cutoffs and unverified TradingView UI import.
The personal registry must bind Core to its currently published Global parent, not merely to any
older superset. Native universes and the existing Global release remain unchanged.
