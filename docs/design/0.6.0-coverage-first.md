# 0.6：先完成市场骨架，再扩展 Beta

日期：2026-10-04。输入：用户 `temp/optimization-01` 的审计报告、机器审计和三份 Core；旧项目 `big-apple/ticker-pool/prompts` 与 `harness/bitpunk_harness/core/pool_*.py`、`harness/hermes/pool_agent.py`；当前 0.5 源码。旧项目和用户原件只读。

## 复盘：迁移了工具，却丢了选择顺序

旧 `_core.md` 要求新增回答“少看到了什么”，删除回答“行业是否还能完整观察”；明确禁止因为 AI 热、消费弱而改变底层覆盖。`phase-survey.md` 先市场结构，`phase-category.md` 再逐一级行业核对产业环节和龙头，最后新增。`pool_agent.py` 分阶段收集判断、局部 repair、再汇总；`pool_ops/pool_validation/pool_render` 确定性应用操作。旧扩展 `pool_ext.py` 与 Core 分开，结构扩展按相对稳定的规模排序；有不同职责的流动性与量化扩展。旧框架的优势是已有精选池与逐行业审查，不是更复杂的运行时天然更聪明。

新架构正确保留了标准库、快照、测量、证据、哈希、可恢复 build、确定性渲染；却把长期维护问题改成了从大候选库填满容量。`_select_stage` 每主题一位代表后按权重和角色桶扩容，桶不足可跨桶补齐；Heavy 仅 50% core，Extreme 35% core，均不是硬上限。`ANCHOR` 的结构标签没有龙头证明，历史构造器每组前两位 anchor 使其余 Core 成员与普通候选竞争。`build_run` 以数量达标判 complete。主题拆细增加保底和权重，热点获得双重预算；Crypto 260 的默认 Heavy 与 53 的 Core 完全失去同档意义。

审计结果：CN Heavy 原证券保留 313/463，US 298/378，Crypto 原代码 47/53。CN 10+11 占证券层由 20.95% 到 32.44%；银行 8→2、酒类 9→2。US 金融总量增加，却丢 WFC/C/USB；软件、医药的大组增加，却把原重要代表延后到 Extreme。Crypto 260→375 的 115 个增量中，风险偏好/游戏/社交占 61。它们是输出结构事实，不等价于已验证的龙头遗漏率或统计 Beta 比例。

## 初版设计与本次 review 后的修订

初版：提高 core 比例、降低主题保底、调回银行消费权重、扩大候选库。

review 后否决仅调参：每组两位银行仍不能覆盖业务分支；扩大候选库不能修复代表排序；高 Core 重合率也可能照抄旧分类。采用以下最终设计：

| 问题 | 最终约束 |
|---|---|
| 热门主题拆分抢预算 | 经济 sector/branch 与展示 theme 独立；父行业绝对额度和稳定权重只管理可选扩展，不按标题数增生 |
| 有 ticker 就算覆盖 | 每个重要 branch 声明最低档位与必要代表；Heavy 必须覆盖全部重要 branch 和已审定必要代表 |
| ANCHOR 标签伪装龙头 | 另有 admission：leader / peer / satellite；需要业务代表性、质量说明及一二级证据；旧角色不自动晋级 |
| 未完成骨架就扩 Beta | 骨架不足停止正式输出，返回可恢复诊断；Light/Medium 不收 satellite；Heavy 上限 20%，Extreme 35%（工程起点，可收紧，不是行业定律） |
| Extreme 修补 Heavy | Extreme 必须传入同日期、同计划、已验证 Heavy；所有必要代表先在 Heavy，增量仅合格 satellite |
| 为 45% 扩容灌水 | 预算是上限，允许更少；35% 总卫星上限与旧 45% 扩容目标冲突时，质量优先 |
| Core 缺失无人解释 | 原 TXT 原文及 SHA-256 固化；逐代码 retain/replace/remove/pending，并检查保留/替换实体进入 Heavy；pending 阻止 Heavy/Extreme |
| ETF 代替指数/收益率 | references 独立于证券预算与测量因子；保留工具种类、观察对象、原始代码和证据；与实体层共同导出 TXT |
| Crypto 同生态重复 | admission 声明 ecosystem_id/token_role；稳定 branch 必须表达具体职能；卫星声明 distinct_from、增量理由，同生态不同代币不自动算两条网络 |

Light 是精简的纯龙头层，不表示容纳整个市场所有龙头；Medium 至少覆盖计划中 70% 的经审定 leader；Heavy/Extreme 包含全部经审定 leader 和必要 peer。比例按同一份覆盖计划核验，不声称对未知的全市场龙头作统计。所有市场走相同流程，市场差异来自研究底表，不增加市场专用选择器。

## 最小技术实现

新增一个 `coverage_core.py`，复用现有候选资格、测量、证据、哈希、渲染、checkpoint；不引入网络运行时、数据库或优化器。默认 policy 使用 coverage-first。历史 0.4/0.5 输入只能显式使用归档 policy 回放，validate 继续验证旧文件完整性，但不把旧输出认证为 0.6 覆盖合格。

研究快照新增 coverage_plan：范围声明、四档实体预算、经济 sector 的稳定权重/容量上限、branch 的必要代表、references、Core 迁移记录。候选新增 admission，保存选择角色、经济 branch、最低档位、业务/质量证据；satellite 另外需要已测 Beta 和对骨架的独立增量。业务判断由 agent 完成，代码验证声明闭合、一致性、预算、覆盖、身份与可追溯性；代码不会根据字段非空证明公司真是龙头。

顺序：normalize → 骨架与迁移审计 → 按档位纳入必要代表 → 验证 Heavy → 在父行业剩余额度内排序合格 Beta → 再验收 → 脚本渲染。扩展排序先父行业权重/已持有数量，再证据合格候选的既有测量分数；展示主题顺序、数量与权重不参与经济预算。达标且未用满预算是 complete，骨架不完整是 needs_research，严禁输出伪合格 Extreme。

Reference 不伪装为普通候选而绕过原资格验证，独立契约检查强证据、时点、工具种类与观察对象。直接指数、收益率可没有成交量，仍计入 TradingView 1,000-token 总上限，不占实体名额。ETF 与指数、现货与合约不自动等价。

维护沿用当前变更操作，最终同样执行覆盖验收；涉及计划或 Core 决策变化时重新研究并 build Heavy，再生成 Extreme，不允许通过 MOVE/REMOVE 绕过骨架门槛。

## 市场研究规则

CN：优先核对银行的全国/股份制/区域角色，保险承保类别，发电运营类型，消费子类，农业；光通信与电网设备分离。US：按美国上市范围而非美国本土范围，核对银行、承保/经纪、软件功能、药物/器械、物流、公用事业和消费业态；HAS 的玩具/IP 不得算家庭日化。Crypto：保留明确的多交易场所范围，BTC/ETH/SOL 属于实体层；XAUT 的黄金价格暴露与 RWA 协议不同，VET/VTHO 生态关系不能当两条网络。GRAM/STX 等先核对身份/资格，PEPE 合约单位、KHC 前缀需要明确转换，不自动恢复字符串。

旧 Crypto ADD 五闸是特定版本的严格新币策略，不能照搬成所有既有网络龙头都必须有持币人收入的通用门槛。保留其思想：盘口先行、真实使用/价值承接、供给风险、残差信息、准入严于留任；新卫星必须满足现有测量门槛并解释信息增量。行业特定事实仍需研究，不凭全局 quality 分数替代。

## 验收与交付边界

测试必须覆盖：银行骨架先于高分半导体；主题拆分/重排/热度变化不改骨架；缺必要代表失败；未标注旧 anchor 不获认证；Light/Medium 无卫星；Heavy/Extreme 硬上限；Extreme 未传或传不合格/不同计划 Heavy 失败；Core 删改/工具转换必须解释；参考层保留且不挤预算；维护和 revalidate 不能绕过；可恢复失败修补后继续。

对三份用户 Core 和上一轮六个输出生成逐项迁移审计结果（temp），保留原件。它们是研究队列，不是自动认证的新生产池。本任务不凭原 TXT 补写一千家公司的财务与领导地位证据；未完成逐项研究时，新的严格生成器应诚实阻止正式发布。修复完成意味着新契约与回归通过，不意味着旧候选现在全是已验证龙头，也不意味着 TradingView 导入或后续交易效果已实测。
