# Methodology

A universe observes economic structure, leadership and supplementary information. A member must
explain what observation would be lost if removed. Popularity or recent returns are insufficient.

## Research and selection

1. Define stable economic sectors/branches and necessary representatives before optional candidates.
   Classify by primary business/protocol function, earnings/token value capture, persistent drivers,
   then supply-chain/network position. Provider labels discover candidates; they do not assign duties.
2. Research core leadership and continuing quality. Market cap, turnover and low R² alone do not
   establish either. Deletions explain surviving coverage or an evidence-backed retirement of scope.
3. Python validates plan, identity and admissions; selects every representative due at the depth;
   checks Core migration and branch coverage; then considers qualified Heavy/Max Beta.
4. Heavy optional seats follow stable sector weights. Max follows the frozen Heavy group distribution,
   using `h / (2 * added + 1)` and a ceiling of `ceil(h * total_added / H)` per group.
   Rank eligible Beta by sourced market cap inside this distribution. Stop at minimum qualified growth.
5. Revalidate, hash and render. Incomplete coverage blocks publication; bounded growth-only gaps may
   be explicit partials. See [coverage](coverage-plan.md), [depths](tier-profiles.md) and [recovery](recovery.md).

Display themes never allocate economic budgets. Merge sparse adjacent groups without losing duties;
news heat, provider inventory and more headings do not increase capacity. Keep direct gauges
separate from company/token entities. Light/Medium rebuild from the same roster for nesting;
Max retains Heavy's exact facts. Changed Heavy requires a new Max.

## Observation roles

Each member has one primary role; admission kind records its selection function separately.

| Role | Observation | Legacy bucket |
|---|---|---|
| `BENCHMARK` | Market/style/sector gauge | core |
| `ANCHOR` | Structural anchor | core |
| `THEME_LEADER` | Theme leadership | core |
| `QUALITY_LEADER` | Business durability/asset quality | core |
| `BETA_SATELLITE` | Supplementary business/token coverage | satellite |
| `INDEPENDENT_SENSOR` | Residual price information | satellite |
| `BREADTH_PROXY` | Breadth/supply-chain observation | satellite |
| `LIQUIDITY_SENSOR` | Turnover/speculative appetite | tactical |
| `NEW_LISTING` | Newly listed observation | tactical |

Current coverage builds admit satellites as `BETA_SATELLITE`; other satellite/tactical roles remain
for explicit legacy replay. Beta requires broad business identity, named-core complementarity and
sourced cap, not detailed profitability/tokenomics. Price factors are optional descriptors;
claims of high price beta or independence require measurements. Crypto cap is circulating USD, never FDV.

Facts and judgements live in structured snapshots. Python does not infer fields from prose or
replace missing values with zero. Source dates, units, measurement method/population and input
hashes make results reproducible. Equity factors use theme gauges; Crypto uses its actual core
factor set. Legacy composite scores apply only to archived replay.
